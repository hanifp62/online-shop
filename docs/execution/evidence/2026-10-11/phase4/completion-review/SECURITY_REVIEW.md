# Security review — uncommitted backend, 2026-10-11

Scope: read-only inspection of current uncommitted backend diff, untracked `BackendPermissionAuditTest.php` and `RescueBackendAuditTest.php`, relevant existing routes/views/middleware, and `completion-backend` evidence. Frontend changes intentionally not reviewed. No credentials, cookies, `.env`, database, or ports 8000/8001 accessed. No source edits, commits, or live requests. Tools available: `read`, `shell`, `grep`; no blocked filesystem access.

## Findings

1. **MEDIUM — Remaining guard's session ID and CSRF token survive logout.** `app/Http/Controllers/AuthController.php:84-95` and `app/Http/Controllers/AdminAuthController.php:36-48`: when both guards are authenticated, logout removes only one guard's session key and skips both session invalidation and token regeneration. Laravel `SessionGuard::logout()` removes its own key (`vendor/laravel/framework/src/Illuminate/Auth/SessionGuard.php:714-724`), not the other guard's session or the session ID. A previously captured shared session remains valid for the other role after either logout; this matters most when a customer signs out while an admin remains logged in. Rotate/destroy the old session ID while retaining the other guard's session data, then regenerate the CSRF token, on both branches. Do **not** call `invalidate()` with another guard active because that would erase the other login. The tests at `tests/Feature/RescueBackendAuditTest.php:193-228` assert preserved authentication only; they do not compare session IDs/tokens or replay the pre-logout ID. `completion-backend/RESULT.md:19,30` explicitly marks dual-guard rotation/replay untested.

2. **LOW — CSP not even in report-only mode; explicit inventory required before enforcement.** `app/Http/Middleware/SecurityHeaders.php:13-20` sets other security headers but neither `Content-Security-Policy` nor `Content-Security-Policy-Report-Only`; `tests/Feature/RescueBackendAuditTest.php:413-423` does not assert either. This is defense-in-depth, not evidence of a new exploitable XSS. Current inventory includes inline scripts (`resources/views/welcome.blade.php:38-48,723` and `public/prototype/index.html:9`), inline event handlers (`resources/views/admin/dashboard.blade.php:122,186,315`, `resources/views/partials/product-footer.blade.php:20`, `resources/views/welcome.blade.php:450,644`), inline styles (`resources/views/welcome.blade.php:49` and other Blade templates), external Bunny fonts (`resources/views/products/show.blade.php:21`), Unsplash images (`resources/views/products/show.blade.php:22`), Vite assets (`resources/views/welcome.blade.php:37`), and local `zafira-core.js` (`resources/views/welcome.blade.php:48`). These are representative, not exhaustive. Inventory actual script/style/image/font/connect/frame origins and inline usage per served surface; deploy report-only and inspect violations before proposing enforced policy. A strict policy applied immediately would break existing UI. No CSP report collection or deployment-header audit was performed.

## Covered by source/tests or supplied evidence

- Admin intended-route fix: `app/Http/Controllers/AdminAuthController.php:24-28` directs successful admin login to dashboard, avoiding customer `/akun`; `tests/Feature/RescueBackendAuditTest.php:29-38` covers it. Tradeoff: intended admin destination no longer restored; current `routes/web.php:57-69` has only one protected admin GET.
- Auth boundaries: `routes/web.php:30-69` separates `auth` and `auth:admin`; the untracked permission test covers guest/customer rejection of admin endpoints at `tests/Feature/BackendPermissionAuditTest.php:21-45`. Tests exercise foreign IDs and forged `user_id`/`status` (`BackendPermissionAuditTest.php:47-85`, `RescueBackendAuditTest.php:94-131`). No IDOR found in this scope.
- Input and XSS: array email stays uncast until validation (`app/Http/Controllers/Controller.php:13-20`), login password is string-validated (`AuthController.php:59-63`, `AdminAuthController.php:19-22`), concierge item slug/quantity/monogram rules are at `StorefrontController.php:149-155`. JSON-LD uses `JSON_HEX_TAG` (`StorefrontController.php:52-60,92-108`) and admin confirm messages use `@js` (`resources/views/admin/dashboard.blade.php:122,186,315`). - CSRF: write routes use POST/PATCH/DELETE in `routes/web.php:23-69`, Blade forms use `@csrf`, and no CSRF middleware exception found in `bootstrap/app.php`. `RescueBackendAuditTest.php:149-191` explicitly re-enables CSRF middleware in tests and checks tokenless newsletter/logout rejection. `completion-backend/RESULT.md:21` says browser newsletter/concierge requests used tokens; public-form click path was not tested.
